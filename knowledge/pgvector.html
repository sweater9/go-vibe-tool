pgvector (Vector Search in PostgreSQL)

databasefreshness: volatilesources not yet verified

pgvector is a PostgreSQL extension that adds a vector column type and similarity search, letting you keep embeddings alongside relational data.

Short answer: pgvector lets you store embeddings in Postgres and query nearest neighbours with SQL, with exact search or approximate indexes (HNSW, IVFFlat). It suits small-to-mid scale and combined relational + vector queries; dedicated vector databases may suit extreme scale.

What is it?

If you already use PostgreSQL, pgvector lets you add "search by meaning" without a new database: store each item's embedding in a column and ask for the closest ones using normal SQL.

Also known as: pgvector, postgres vector search, postgres embeddings, HNSW index postgres, IVFFlat, vector column postgres, semantic search in postgres, pgvector vs pinecone.

Technical definition

The extension provides vector types and distance operators (L2, inner product, cosine) with exact scan and ANN indexes (HNSW, IVFFlat). Benefits: transactional consistency, joins, filters and existing operations tooling; trade-offs: memory use of indexes, recall/speed tuning and scaling characteristics versus specialised systems. Version features (e.g. half-precision, sparse or binary vectors) change; check current docs and your managed-Postgres provider's support.

Entity type: database · Freshness class: volatile.

When should I use it?

Good first choice when already on Postgres and scale is moderate.

Implementation patterns

  • Embeddings column beside the source row; filter with SQL then order by distance.
  • HNSW index for recall/latency balance.
  • Combine with Postgres full-text search for hybrid retrieval.
  • Keep the embedding model/version in a column.

Technologies and frameworks

Commonly associated: PostgreSQL, pgvector, HNSW / IVFFlat, managed Postgres services. Names are examples of what exists, not recommendations, and projects change quickly.

Practical guide

  1. Enable the extension.
  2. Choose vector dimension from your embedding model.
  3. Insert embeddings.
  4. Create an ANN index.
  5. Measure recall vs latency.

Common failure modes

  • No index at scale (slow sequential scans).
  • Index memory exceeding RAM.
  • Mixing embedding models in one column.
  • Recall loss from aggressive ANN settings.

Troubleshooting

  • Slow similarity queries — Add an HNSW/IVFFlat index and tune search parameters.
  • Results missing relevant rows — Increase ef_search/probes; verify filters do not over-prune.
