RAG Evaluation (Retrieval and Answer Quality)

techniquefreshness: evolvingsources not yet verified

Evaluate a RAG system in two layers: did retrieval find the right passages, and did the generator answer faithfully and completely from them? Measure both separately.

Short answer: Measure retrieval (recall@k, precision, nDCG, MRR) and generation (faithfulness/groundedness, answer relevance, completeness, correct abstention). Use a labelled question set; automate with judges; spot-check by hand.

What is it?

When a RAG answer is wrong, either the system fetched the wrong material or the model misused the right material. Testing the two parts separately tells you which to fix.

Also known as: evaluate RAG, RAG metrics, RAGAS, faithfulness metric, groundedness, recall@k, context precision, context recall.

Technical definition

Retrieval metrics require relevance labels (which chunks answer each question): recall@k, precision@k, MRR, nDCG. Generation metrics include faithfulness (are claims supported by retrieved context?), answer relevance, context utilisation and abstention accuracy; automated frameworks such as RAGAS (Es et al., 2023) and ARES (Saad-Falcon et al., 2023) use LLM judges (LLM-as-a-Judge) and need calibration. End-to-end correctness against gold answers complements component metrics. Include unanswerable and adversarial questions.

Entity type: technique · Freshness class: evolving.

When should I use it?

Run before launch and on every pipeline change.

Prerequisites and related concepts

Understand these first: What is RAG (Retrieval-Augmented Generation)?, How to Evaluate AI Systems and Outputs.

Related concepts: LLM-as-a-Judge, Hybrid Search and Reranking, Chunking: How to Split Documents for RAG, AI Hallucinations: Why Models Make Things Up, How to Reduce AI Hallucinations, Agentic RAG (Adaptive and Self-Correcting Retrieval).

Implementation patterns

  • Build 50–200 questions with gold passages and answers.
  • Compute retrieval metrics before generation.
  • Judge faithfulness against retrieved context.
  • Add unanswerable questions to test abstention.
  • Track metrics per change.

Technologies and frameworks

Commonly associated: RAGAS, ARES, TruLens-style tooling, custom harnesses. Names are examples of what exists, not recommendations, and projects change quickly.

Practical guide

  1. Collect realistic questions.
  2. Label relevant chunks.
  3. Score retrieval.
  4. Score faithfulness and correctness.
  5. Segment failures and fix the largest bucket.

Common failure modes

  • Only end-to-end scoring, hiding the failing component.
  • Uncalibrated LLM judges.
  • Test questions written from the chunks (too easy).
  • No negative/unanswerable cases.

Troubleshooting

  • Good retrieval, bad answers — Tighten the prompt, reduce context noise, require citations.
  • Bad retrieval — Revisit chunking, embeddings, hybrid search and reranking.
