Local and Self-Hosted LLM Runtimes Compared

conceptfreshness: volatilesources not yet verified

llama.cpp, Ollama, vLLM, ONNX Runtime and Hugging Face Transformers serve different needs: personal local use, multi-user GPU serving, portable deployment or general experimentation.

Short answer: Personal laptop: Ollama or llama.cpp. Multi-user GPU server: vLLM (or similar). Portable/browser/edge: ONNX Runtime or llama.cpp builds. Research/fine-tuning: Transformers + PyTorch. Verify model/hardware support before committing.

What is it?

"What should I run my model with?" depends on who is using it and on what hardware. One person on a laptop wants something easy; a team serving hundreds of users wants throughput; an app that runs in the browser wants something portable.

Also known as: ollama vs vllm, llama.cpp vs ollama vs vllm, what should I use to run LLMs locally, best way to host an open model, self host LLM options, which inference engine should I use, local LLM runtime comparison.

Technologies and frameworks

Commonly associated: Ollama, llama.cpp, vLLM, ONNX Runtime, Hugging Face Transformers. Names are examples of what exists, not recommendations, and projects change quickly.

Practical guide

  1. Count concurrent users.
  2. Check hardware.
  3. Check model/format support.
  4. Prototype two options.
  5. Load-test.

Common failure modes

  • Using a single-user runtime for production traffic.
  • Ignoring memory needs.

Troubleshooting

  • Slow under multiple users — Move to a batching server like vLLM or add replicas.
