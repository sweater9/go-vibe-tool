FlashAttention-3 (and FlashAttention-4)

techniquefreshness: volatilekey claims checked 2026-10-09

FlashAttention-3 is an exact attention implementation redesigned for NVIDIA Hopper GPUs. It overlaps data movement and computation, interleaves matrix multiplication with softmax, and uses FP8 low-precision, reaching up to about 740 TFLOPs/s in FP16 on H100.

Short answer: FlashAttention-3 (Shah et al., 2024) makes exact attention faster on Hopper (H100) GPUs using three techniques: asynchrony (overlap data movement and compute with warp specialisation), interleaving matmul and softmax, and FP8 with block quantisation and incoherent processing. Paper claims: 1.5–2.0× over FlashAttention-2, up to ~740 TFLOPs/s FP16 (75% utilisation), ~1.2 PFLOPs/s FP8. A FlashAttention-4 package for Hopper and Blackwell also exists.

What is it?

FlashAttention already avoided wasting memory bandwidth. The next problem was that new GPUs (the H100) can do several things at once, and FlashAttention-2 left much of that on the table. FlashAttention-3 reorganises the work so loading data, multiplying matrices and computing softmax overlap instead of waiting for each other, and it can use the GPU's faster 8-bit floating-point maths. The answer is the same attention, computed faster.

Also known as: FlashAttention-3, FlashAttention 3, FA3, flash attention 3, FlashAttention-4, FA4, Hopper attention kernel, H100 attention.

Technical definition

The paper (Shah, Bikshandi, Zhang, Thakkar, Ramani and Dao, 2024; arXiv:2407.08608) states that FlashAttention-2 achieved only 35% utilisation on H100 and proposes three techniques for Hopper GPUs: exploiting the asynchrony of Tensor Cores and the Tensor Memory Accelerator (TMA) to overlap computation and data movement through warp specialisation; interleaving block-wise matrix multiplication and softmax; and block quantisation with incoherent processing to exploit hardware FP8 support. Reported results: 1.5–2.0× speedup on H100 with FP16 reaching up to 740 TFLOPs/s (75% utilisation), FP8 close to 1.2 PFLOPs/s, and FP8 FlashAttention-3 with 2.6× lower numerical error than a baseline FP8 attention. These are the authors' measurements on specific hardware and shapes. The repository README (as read on the check date) describes FlashAttention-3 as a beta release for H100/H800 GPUs, CUDA 12.3 or later (12.8 recommended), supporting FP16/BF16 forward and backward and FP8 forward; and describes FlashAttention-4, written in CuTeDSL, as optimised for Hopper and Blackwell GPUs and installable as flash-attn-4. Because FlashAttention-3 is exact attention in the same sense as FlashAttention, quality is unchanged apart from low-precision effects when FP8 is used.

When should I use it?

Relevant when training or serving transformers on H100/H800 (or newer) GPUs. Usually enabled through a framework rather than hand-written.

Implementation patterns

  • Let the framework or serving engine select the best attention backend for your GPU.
  • Benchmark FP16/BF16 first; trial FP8 only with an accuracy check.
  • Pin library, CUDA and PyTorch versions together.

Technologies and frameworks

Commonly associated: flash-attn library, Hopper (H100/H800), Tensor Cores, TMA, FP8, CuTeDSL, PyTorch SDPA. Names are examples of what exists, not recommendations, and projects change quickly.

Practical guide

  1. Identify your GPU architecture.
  2. Use your framework's default attention backend and read its logs for the kernel chosen.
  3. Benchmark with your real sequence lengths and batch sizes.
  4. Evaluate quality before any FP8 use.
  5. Re-check the README for current requirements and status.

Common failure modes

  • Expecting Hopper-only speedups on older GPUs.
  • Installing a beta build into production without testing.
  • Turning on FP8 without checking quality.
  • Quoting peak TFLOPs from the paper as expected end-to-end speedup.

Troubleshooting

  • Build or import errors — Match the library with CUDA (12.3+ per the README), PyTorch and GPU architecture.
  • No speedup — Check the GPU is Hopper and the backend is actually selected; other GPUs need other kernels.
  • Accuracy drop with FP8 — Fall back to BF16 or evaluate on your own tasks.

Contrasted with

  • FlashAttention — The original IO-aware algorithm; FlashAttention-3 targets Hopper-specific hardware features.
  • Quantization of AI Models — FP8 attention quantises the attention computation; weight quantisation shrinks stored weights.
