The ReAct Pattern (Reason + Act)

techniquefreshness: evolvingsources not yet verified

ReAct interleaves reasoning steps with actions: the model decides what to do, calls a tool, reads the observation and reasons again, forming the basic agent loop.

Short answer: ReAct = think → act (tool call) → observe → repeat. It underlies most tool-using agents; make loops safe with step limits, validated tools and clear stopping criteria. Reasoning shown in the loop is working text, not a guaranteed explanation.

What is it?

ReAct is the basic recipe for an AI agent: decide on a next step, use a tool, look at what came back, and decide again. Most agent frameworks implement some version of it.

Also known as: ReAct, reason and act, ReAct prompting, thought action observation, agent loop, tool use loop, ReAct agent.

Technical definition

Yao et al. (2022) propose prompting models to alternate "thought" and "action" steps with observations, improving performance on knowledge-intensive and interactive tasks versus reasoning-only or acting-only baselines. Modern implementations use native tool-calling APIs (Function Calling (Tool Calling) Explained) instead of text parsing, and may use hidden or summarised reasoning (Reasoning Transparency and Hidden Reasoning). Reliability depends on tool design, error handling and termination logic.

Entity type: technique · Freshness class: evolving.

When should I use it?

The default pattern for exploratory tasks needing tools.

Prerequisites and related concepts

Understand these first: What are AI Agents?, Agent Tools: How AI Agents Take Actions, Function Calling (Tool Calling) Explained.

Related concepts: Agent Planning and Task Decomposition, Chain-of-Thought Prompting, AI Agent Frameworks Compared, Agentic Workflows: Patterns for Reliable AI Automation, What are AI Agents?.

Implementation patterns

  • Loop: model → tool call → result → model, with a hard step cap.
  • Validate tool args; return concise, informative errors.
  • Add a "finish" tool or explicit stop condition.
  • Log each step for debugging.

Technologies and frameworks

Commonly associated: native tool-calling APIs, LangGraph, OpenAI Agents SDK, custom loops. Names are examples of what exists, not recommendations, and projects change quickly.

Practical guide

  1. Define tools with clear schemas.
  2. Implement the loop with limits.
  3. Add stop conditions.
  4. Trace runs.
  5. Evaluate on tasks (Agent Evaluation).

Common failure modes

  • Infinite or oscillating loops.
  • Context bloat from verbose tool outputs.
  • Wrong tool selection from vague descriptions.
  • Acting on injected instructions in tool output.

Troubleshooting

  • Agent repeats the same call — Detect repeats, add loop limits and hint in the error message.
  • Context overflows — Truncate/summarise tool results; store large data outside the prompt.

Contrasted with

  • Agent Planning and Task Decomposition — ReAct decides step by step; planning-first agents draft a multi-step plan upfront.
  • Chain-of-Thought Prompting — CoT reasons without acting; ReAct interleaves actions with observations.
