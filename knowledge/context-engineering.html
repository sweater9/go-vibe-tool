Context Engineering

conceptfreshness: volatilesources not yet verified

Context engineering is deciding what goes into a model's context window — instructions, retrieved facts, tool results, memory, examples — and in what form, to make agents reliable.

Short answer: Beyond writing a prompt, context engineering curates everything the model sees each turn: system instructions, relevant memory, retrieved documents, tool definitions and results, trimmed history. Less, better-organised context usually beats more.

What is it?

A model only knows what's in front of it. Context engineering is the craft of putting the right information in front of it at the right time — and leaving the rest out — so it can do the job without being distracted or confused.

Also known as: context engineering, context management, context curation, context rot, managing context windows for agents, prompt vs context engineering, context pruning, context compaction.

Technical definition

The term gained currency in practitioner discussions in 2025 to describe the broader discipline around prompt engineering for agentic systems (verify provenance of the term if attributing it). Elements: instruction hierarchy (What is a System Prompt?), retrieval (What is RAG (Retrieval-Augmented Generation)?), memory selection and summarisation (Agent Memory: Short-Term, Long-Term and Beyond), tool-set selection and result trimming (Agent Tools: How AI Agents Take Actions), caching of stable prefixes (Prompt Caching), and isolating sub-tasks into separate contexts (Multi-Agent Systems Explained). Research on long-context use suggests models may use information unevenly across a long context, so organisation and pruning matter.

Entity type: concept · Freshness class: volatile.

When should I use it?

Central to building agents and RAG systems that stay reliable over many steps.

Prerequisites and related concepts

Understand these first: Prompt Engineering: How to Write Better AI Prompts, What is a Context Window?.

Implementation patterns

  • Keep stable instructions first; dynamic content later (cache-friendly).
  • Just-in-time retrieval instead of preloading.
  • Compact old turns into summaries; keep key decisions verbatim.
  • Offload large artefacts to files/stores and pass references.
  • Give each sub-agent a minimal context.

Technologies and frameworks

Commonly associated: retrieval pipelines, summarisation/compaction, prompt caching, tool-search/selection. Names are examples of what exists, not recommendations, and projects change quickly.

Practical guide

  1. Inventory what enters context each turn.
  2. Remove what is not needed.
  3. Order for clarity and caching.
  4. Add compaction rules.
  5. Test long-run behaviour (How to Evaluate AI Systems and Outputs).

Common failure modes

  • Dumping everything "to be safe".
  • Contradictory instructions across layers.
  • Stale summaries treated as fact.
  • Tool lists so long that selection degrades.
  • Sensitive data pulled into context unnecessarily.

Troubleshooting

  • Agent drifts on long tasks — Re-state the goal; compact history; keep a short task state.
  • Quality drops as context grows — Prune irrelevant material; reorder; retrieve less but better.

Contrasted with

  • Prompt Engineering: How to Write Better AI Prompts — Prompt engineering focuses on wording instructions; context engineering manages the whole information payload across turns.
