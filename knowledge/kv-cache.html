KV Cache

techniquefreshness: evolvingsources not yet verified

The KV cache stores attention keys and values for past tokens so a model need not recompute them while generating, trading memory for speed.

Short answer: During generation, the model caches keys and values of earlier tokens, so each new token only computes its own attention. The cache grows with context length and batch size, making memory the main serving limit.

What is it?

When a model writes a long answer, it would be wasteful to re-read the whole conversation for every new word. It stores intermediate results (the "KV cache") from earlier words and reuses them. That makes generation faster but uses a lot of memory as the conversation grows.

Also known as: key value cache, KV caching, attention cache, grouped query attention, GQA, multi-query attention, PagedAttention, prefix cache.

Technical definition

For each layer, keys and values of previous tokens are retained, giving per-token decode cost linear in context but memory O(layers × heads × head_dim × tokens × batch). Techniques to reduce or manage it: multi-query and grouped-query attention (Shazeer, 2019; Ainslie et al., 2023), PagedAttention (Kwon et al., 2023, vLLM), cache quantisation, prefix caching and eviction/compression policies. Prompt-caching features offered by providers reuse computed prefixes (Prompt Caching).

Entity type: technique · Freshness class: evolving.

When should I use it?

Matters when serving LLMs or when you hit memory limits at long context.

Prerequisites and related concepts

Understand these first: What is a Transformer? (Attention Explained), What is a Context Window?.

Related concepts: Attention Sinks and StreamingLLM, vLLM, Prompt Caching, FlashAttention, Model Serving and Inference Infrastructure, State Space Models (Mamba and S4), Quantization of AI Models.

Implementation patterns

  • Paged KV memory management.
  • GQA/MQA models to shrink cache size.
  • Prefix/prompt caching for shared system prompts.
  • KV quantisation for long contexts.

Technologies and frameworks

Commonly associated: vLLM PagedAttention, llama.cpp, TensorRT-LLM. Names are examples of what exists, not recommendations, and projects change quickly.

Practical guide

  1. Estimate cache size per token for your model.
  2. Multiply by context and concurrency.
  3. Choose a serving engine with paged KV.
  4. Stabilise shared prefixes.

Common failure modes

  • Out-of-memory at long context or high concurrency.
  • Fragmentation wasting memory.
  • Cache invalidated by tiny prompt changes.

Troubleshooting

  • OOM with many concurrent users — Reduce max context/batch, use paged KV engines, quantise cache, or use a GQA model.
  • Latency high on repeated prompts — Use prefix caching and keep shared prefixes stable.

Contrasted with

  • Prompt Caching — Prompt caching is a provider billing/latency feature built on reusing cached prefixes; the KV cache is the underlying data structure.
