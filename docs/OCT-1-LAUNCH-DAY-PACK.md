## Response templates

### Feature request
Thanks — that’s useful context. I’m recording the workflow rather than rushing a feature into production today. What would the ideal result look like for you?

### Bug report
Thanks for flagging it. Could you share the browser/device and the step where it fails? I’ll treat reproducible launch-blocking issues as priority fixes.

### Privacy question
Many IntelliTools workflows are designed to process inputs in the browser where technically possible. The individual tool page explains its relevant limitations; I avoid claiming that every possible workflow is entirely local.

### “Why another tools site?”
The aim isn’t the raw number of utilities. It’s reducing the repeated search → new site → new interface → new account cycle, while making useful tools easy to find again through favourites and recently used shortcuts.

### Positive feedback
Thank you. Which tool or workflow was the useful part for you? That signal helps decide where IntelliTools should go next.

## What to record during the 24 hours

Keep a simple log with:
- time
- source
- tool mentioned
- bug / UX friction / feature request / positive signal
- exact user need
- action needed
- whether it requires a production change.

Do not infer demand from votes alone. Specific tool mentions, repeat-use intent, concrete workflow problems and reproducible friction are stronger product signals.

## Production-change gate

A launch-day change should pass all four checks:
1. It fixes a reproducible bug or severe UX blocker.
2. It is small and isolated.
3. It can be tested before deployment.
4. Failure would not jeopardize unrelated tools.

Otherwise, log it for post-launch review.

## End-of-day review

Capture:
- Product Hunt engagement and qualitative feedback available in the dashboard.
- Most-mentioned IntelliTools tools.
- Reproducible bugs.
- Repeated workflow requests.
- Landing-page or positioning confusion.
- Any production fixes made.

Then compare these signals with Search Console data at the scheduled growth review before deciding the next SEO pages or V2.1 tools.
